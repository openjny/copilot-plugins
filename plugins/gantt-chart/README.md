# gantt-chart

ガントチャートを編集できる canvas (`openjny-gantt-chart`) を追加するプラグインです。チャートは 1 つの JSON ファイルに保存されます。ユーザーは画面で、エージェントは action で、同じファイルを編集します。

<img width="1670" height="1059" alt="image" src="https://github.com/user-attachments/assets/98ce66e0-462a-42d2-b4bc-ab1a236fdc89" />

## 開き方

エージェントに「`plan.gantt.json` でガントチャートを開いて」と頼むか、canvas を開いて画面でパスを入力します。存在しないパスを指定すると、新しいチャートを作ります。拡張子は `.json` にしてください。

## 画面でできること

| 操作 | 方法 |
|:--|:--|
| タスクの追加・削除・インデント・並べ替え | ツールバー。タスク名の列を開いているときは、一覧のキー操作（矢印、Enter、Delete）も使えます |
| 名前の変更 | 詳細パネルの「タスク名」。タスク名の列を開いているときは、タスク名のダブルクリックでも変更できます |
| 詳細の表示 | タスク（バー、一覧の行）をクリックすると、画面の下に詳細パネルが開きます。パネルは小さめで、中身はパネルの中でスクロールします。×か Esc で閉じます。開いている間は、矢印キーでの選択にも追従します |
| 日付の移動・期間の変更 | バーをドラッグ（右端で期間を変更）。タイムラインの端にポインターを寄せると、自動でスクロールします |
| 複数のタスクを選ぶ | Ctrl+クリックで追加・解除、Shift+クリックで範囲を選択（バーでも一覧の行でも）。何もない場所からドラッグすると、四角で囲んだバーを選べます（Ctrl を押しながらだと追加）。Esc で 1 件に戻します |
| 複数のタスクを一緒に動かす | 選択中のバーを 1 つドラッグすると、全部が相対位置を保ったまま同じ稼働日数だけ動きます。親タスクのバーをドラッグすると、子タスクがまとめて動きます。どれかが先行タスクの終了前になる動きは、その手前で止まります。複数選択中は、削除・インデント・並べ替えは使えません |
| 依存関係をつなぐ | 選択中のバーの上か下にポインターを寄せると、半透明の矢印が出ます（左右は期間の調整に使うので出しません）。上のオレンジの▲は先行タスク（このタスクの前に済ませるもの）、下の青の▼は後続タスク（このタスクの後に始めるもの）につなぎます。矢印はポインターに合わせてバーに沿って動きます。別のタスクへドラッグするか、矢印をクリックしてからタスクをクリックするとつながります。Esc で取り消します。重複や循環になる相手は理由を出して断ります。親タスクは先行タスクを持てないので、下の▼だけです |
| 進捗・工数・担当・色ラベル・先行タスク・メモ | 下の詳細パネル |
| 休日・プロジェクト名 | ヘッダーの「プロジェクト」ボタン（ダイアログ） |
| 日・週・月の切り替え | ヘッダーの「日 / 週 / 月」、または Ctrl+↑（日の方向）/ Ctrl+↓（月の方向）。表示の中央にある日付を保ったまま切り替わります。入力欄にフォーカスがあるときは切り替わりません |
| 過去・未来へのスクロール | タイムラインは、最初のタスクより前、最後のタスクより後ろにも、少なくとも 1 画面分の余白があります。左右どちらの端までスクロールしても、日付の範囲が自動で延びます |
| 依存関係の確認 | タスクを選ぶと、そのタスクに出入りする矢印が青で強調され、他の矢印は薄くなります |
| タスク名・期間・担当の表示・非表示 | ツールバー左端のボタン（VS Code の左パネルと同じ形）で切り替えます。「#」（行番号）は常に左に表示します。既定は畳んだ状態で、タイムラインが広がり、バーにタスク名が出ます。開くと、タスク名・期間・担当が「#」の右に出ます |
| ライト・ダークの切り替え | ヘッダーの太陽・月・モニターのボタン（モニターは OS の設定に合わせます） |
| 保存済みの状態に戻す | 「バージョン」 |
| JSON の書き出し | 「JSON エクスポート」（バージョンは含みません） |

## 日程の決まり方

- 期間は稼働日で数えます。土曜、日曜、プロジェクトの休日は稼働日に含めません。`1w` は 5 稼働日です。
- 先行タスクがあるタスクは、先行タスクの終了の翌稼働日にラグ（稼働日、0 以上）を足した日に始まります。バーを動かすと、開始日ではなくラグが変わります。先行タスクの終了前に開始する変更は、ドラッグ、詳細パネル、action のいずれでも、先行タスクが許す最初の日に補正されます。負のラグは受け付けません。
- 子タスクを持つタスク（親タスク）の日付、進捗、工数は、子タスクから自動で決まります。進捗は子タスクの期間で重み付けします。
- 先行タスクが循環する変更は受け付けません。

## ファイル形式

`format` と `version` で判定します。違うファイルや新しい version は、上書きせずに画面へエラーを出します。負のラグ（先行タスクの終了前の開始）を含むファイルも同様にエラーになるので、`lag` を 0 以上に直してください。1 タスクが 1 行なので、直接編集もできます。外部での変更は約 1 秒で画面に反映されます。

```json
{
  "format": "openjny-gantt-chart",
  "version": 1,
  "project": {"name": "新製品", "holidays": ["2026-11-23"]},
  "tasks": [
    {"id":"t1","name":"設計","level":0,"start":"2026-11-16","duration":5,"progress":0},
    {"id":"t2","name":"要件定義","level":1,"start":"2026-11-16","duration":2,"progress":0},
    {"id":"t3","name":"基本設計","level":1,"start":"2026-11-18","duration":2,"progress":0,"predecessors":[{"task":"t2","lag":0}]}
  ],
  "snapshots": []
}
```

`level` が階層です。最初のタスクは 0、以降は直前のタスクの `level` + 1 以下にします。

## エージェント向け action

| action | 内容 |
|:--|:--|
| `open_chart` | ファイルを開く（なければ作成） |
| `get_chart` | 全タスクの計算済みの日付、進捗、ユーザーが選択中のタスク（複数なら全部）を読む |
| `edit_chart` | 編集をまとめて適用する（途中で失敗したら何も変えない） |
| `reload` | ファイルを読み直す |

`edit_chart` の `ops` は `add`、`update`、`delete`、`move`、`indent`、`outdent`、`shift`、`slide`、`project`、`snapshot`、`restore`、`delete_snapshot` です。`slide` は `ids` で指したタスク（親タスクは子タスクをまとめて指す）を、相対位置を保ったまま `days` 稼働日だけ動かします。先行タスクの終了前になる分は切り詰めて、結果の `adjusted.days` に動かした日数を返します。項目は action のスキーマに書いてあります。

## 保存先

チャートは指定した JSON ファイルです。最近開いたファイルの一覧を `<copilot-home>/extension-data/openjny-gantt-chart/recent.json` に、選んだテーマを同じ場所の `theme.json` に保存します。
