# 日本語の表現チェック

共通原則と実行手順は [SKILL.md](../SKILL.md) を参照。以下は文章を見直すための目安であり、該当するだけで誤りや AI 生成と断定しない。

## 記号・書式

- 全角・半角を問わず、コロンで行を終えて次の行へつなぐ構成は避ける。「ポイントは以下の通りです。」のように文として閉じる。
- コロンの後に同じ行で本文が続く場合は、自動検出の対象にしない。
- 「」の中に『』を重ねる書き方は、引用の階層が必要か確認する。実際の入れ子の引用や書名まで一律に直さない。
- 補足や留保を括弧に詰め込まない。必要な条件なら本文に組み込む。

## 語尾・リズム

- 「〜です。〜です。〜です。」のように同じ語尾を3文以上続けない。文の長さや構文を変え、です・ます調と常体を無理に混ぜない。
- 「さらに」「また」「したがって」「そのため」の連打を間引く。削っても関係が伝わるなら省き、残すなら1段落に1個を目安にする。
- 「以上がポイントです」「次に進みましょう」「最後にまとめます」で毎段落を閉じない。

## 語彙・構文

- 「サポートする」なら何をするのか、「提供する」なら何をどう渡すのかを書く。「毎週レポートを送る」まで具体化する。
- 「非常に有効」「大きなメリット」「革新的」「包括的」などの評価語は、根拠や比較対象がなければ削る。
- 羅針盤、設計図、エンジン、土台、車の両輪、スパイス、レシピ、筋トレ、DNA、潤滑油などの便利な比喩に頼りすぎない。技術名や文字通りの意味で使う場合は別。
- 「本質的」「最適化」「多角的」「不可欠」「架け橋」が続くなら、具体的な説明に置き換える。必要な専門用語は残す。
- 「正本」のように AI が使いがちな語は、読者に通じる一般的な表現で足りないか確認する。正式な管理用語として使う場合は残す。
- 「フリーランサー」より「フリーランス」、「デーティングアプリ」より「マッチングアプリ」など、日本語圏で定着した語を選ぶ。
- 「することができる」は「できる」や具体的な動詞で短くする。「に他ならない」も、強調が本当に必要か確認する。
- 「ステップ1：〇〇」形式を乱用しない。ただし、参照番号が必要な手順では番号を残す。
- 「以下の3つの観点から説明します」のように、見出しで分かる内容を再宣言しない。

## スタンス・導入

- 「一概には言えませんが」「と言えるでしょう」で結論をぼかさない。判断を示してから条件や不確実性を添える。
- 「結論から言うと」を使うなら、直後に具体的な結論を書く。
- 「メリットもあればデメリットもあります」で終わらず、用途に応じた選択と理由まで書く。
- 「あまり推奨されません」のような遠回しな否定は、理由を添えて明確にする。口調の強さは読者に合わせる。
- 「ご質問ありがとうございます」のような儀礼的な導入や、「いかがでしたか」のような定型の締めは、本文に必要か見直す。
- 「ぶっちゃけ」「正直なところ」や問いかけは、書き手の普段の文体に合う場合だけ使う。

## スクリプトで検出する項目

`--language ja` または `both` で有効。共通の `common.em-dash` も実行される。

語句を追加するときは [rules.json](../scripts/rules.json) の `terms` に登録する。使用禁止語は `severity` を `error`、確認が必要な語は `warning`、参考情報だけを出す語は `info` にする。用途と修正方針が異なる語は、同じ配列へ混ぜず別のルール ID とメッセージに分ける。

| ルール ID | 検出対象 |
| --- | --- |
| `ja.line-ending-colon` | 全角・半角コロンで終わる行 |
| `ja.warning-word` | `rules.json` に登録した AI が使いがちな注意語 |
| `ja.repeated-ending` | 同一段落で同じ語尾が3文連続 |
| `ja.connective-overuse` | 同一段落で対象の接続詞が文頭に2回以上 |

語尾の判定は文字列の末尾一致で、`です` / `ます` / `だろう` / `でしょう` / `である` / `だ` を対象とする。活用や品詞は解析しない。略語・引用・箇条書きなどでは文境界がずれることもあるため、指摘箇所を原文で確かめる。

引用の必要性、根拠の有無、比喩の適切さ、文体の統一、翻訳語の自然さは通読で判断する。上記のガイドラインすべてを自動検出するわけではない。
